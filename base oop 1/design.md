# Проектирование классов — Библиотечная система

## 1. UML-диаграмма классов (PlantUML)

@startuml
class Book {
  - isbn : String
  - author : String
  - title : String
  - isAvailable : boolean
  + getIsbn() : String
  + getAuthor() : String
  + getTitle() : String
  + isAvailable() : boolean
  + markIssued() : void
  + markReturned() : void
}

class Library {
  - books : List
  + addBook(book : Book) : void
  + issueBook(isbn : String) : void
  + returnBook(isbn : String) : void
  + getAllBooks() : List
  + getAvailableBooks() : List
  + getIssuedBooks() : List
  - findBook(isbn : String) : Book
}
@enduml

## 2. Ответы на вопросы

**Вопрос 1. Какие атрибуты Book должны быть неизменяемыми после создания? Почему?**
Неизменяемыми должны быть `isbn`, `author` и `title`. Если поменять ISBN, то это уже будет как будто другая книга, и мы потеряем её в системе. А автор и название — это просто факты о книге, они не меняются. Поэтому мы задаем их один раз при создании и не даем менять. А вот `isAvailable` менять можно, потому что книгу то выдают, то возвращают.

**Вопрос 2. Где должно храниться состояние «книга выдана / доступна» — в классе Book или в классе Library? Обоснуйте.**
Состояние должно храниться в классе `Book`. Это же свойство самой книги — лежит она на полке или у читателя. Если мы запихнем этот статус в `Library` (например, сделаем там отдельный список выданных книг), то легко запутаться: книга может быть в списке выданных, а сама при этом думать, что она на полке. А если статус хранится внутри книги, то `Library` просто дергает её методы, и всё всегда синхронизировано.

**Вопрос 3. Какие методы Library должны быть публичными, а какие — внутренними? Приведите пример метода, который не должен быть публичным, и объясните, что может пойти не так, если его сделать публичным.**
Публичными должны быть основные методы: `addBook`, `issueBook` (выдать), `returnBook` (вернуть) и разные `get` методы, чтобы смотреть списки книг. А вот метод `findBook` (поиск книги) должен быть внутренним (приватным). Если сделать его публичным, то любой другой код сможет найти книгу и напрямую поменять её статус, обойдя метод `issueBook`. Тогда мы сможем выдать одну и ту же книгу дважды, и `Library` об этом даже не узнает. Поэтому поиск скрываем, а менять статус даем только через нормальные методы `Library`.
